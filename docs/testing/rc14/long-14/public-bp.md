# 合成案例：栖链供应协同公司｜季度转型经营会资料
以下企业、数据、人物均为虚构测试材料，单位万元。日期均相对会议日。
## 公司与目标
公司已经营3年，向区域连锁餐饮及其供应商提供对账、缺货异常与供货协同。原业务靠定制项目和驻场，计划转标准订阅。不是求生现金救火；有资源但选择会锁定下一季度经营方式。
案主为CEO，有经营预算和用人权。7个工作日后需向董事会提交下季度90天的一揽子经营决议：主攻客群、出售什么与价格、采用何种销售及渠道边界、如何兑现老客户承诺及迁移、给研发交付多少容量、激励谁、分批投多少资金、用什么证据继续或撤退。需要本场把内部可决定的取舍和责任排清，外部未证实事项写条件；不是只获得“先访谈几个客户”这一项首步。
## 已有业务事实
上年确认收入860：定制530、维护与托管210、接口及实施120；综合毛利34%。客户22：4家全国大连锁贡献410收入、8家区域连锁贡献330、10家小客户120。客户满意但研发常被大客户插单，维护口径未分清。
上年末现金510；未来90天固定支出185，账面预计收款160，获批准可用转型投资上限120（不是要求花满）。独立工程容量季度180人日，产品/设计60人日；老客户合同、售前及维修都需消耗。没有紧迫融资。
产品原有“异常发现—双方确认—处理—对账”主线，但部分客户要自动结算，部分只要导表。标准化不等于重写系统。
## 市场与方案
大客户客单高但每家要求不同；区域连锁流程更像，但支付方与一线使用方分离；小客户偏低价。供应商也可能付费，但怕平台扣点和数据共享。
候选：继续接大项目、面向区域连锁做标准订阅、通过ERP集成商卖、做供应商交易撮合抽佣。董事会未决定主线，不能默认四条都做。
5家客户参加过早期功能试用，两家口头愿付费；没有标准订阅合同。已有报表中的“降低处理时间、减少损耗”未统一计算，不能当已证实价值。
一名ERP伙伴愿意带客户，也希望代理和接口控制；一位大客户愿付升级费用但要求特殊承诺。销售按签约额拿奖，交付按上线拿奖，彼此冲突。
数据来自门店订单和供应商价表，现有协议用于本客户服务；跨客户模型训练和行业benchmark未获授权。
