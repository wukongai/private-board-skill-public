# five-step / 1.0
用途：检查业务流程或产品范围是否值得保留和优化。输入为目标、现行流程、需求来源、关键约束；目标不清先澄清。
依次执行：
1. 质疑需求：谁提出、为哪个目标、依据是什么？先处理最关键的一条。
2. 尝试删减：识别可移除环节；核对责任人、依赖、影响和恢复方式，用可逆小试验证。
3. 简化优化：对必要的剩余环节减少复杂度，不优化尚未证明必要的步骤。
4. 缩短周期：前三步有结论后再提速，同时看质量与效果是否恶化。
5. 自动化：流程必要且相对稳定后再判断自动化收益、维护成本和异常处理。
每轮一个主问题；用户只要求自动化时先核实前置步骤，已有可靠记录可以复用，不重复盘问。临时应急可给带限制的应急建议，但不能声称完成五步法。
输出：当前步骤、保留/删减的理由、下一验证、停止/回滚条件，关联原Q。
停止：删减影响不明，或触及安全、法律、合同等约束且未核实→保留环节并取证；不要把风险容忍当作删除权限。客户价值、服务信任等不可只按工程效率取舍。
来源：[Everyday Astronaut原访谈发布方文章（2021）](https://everydayastronaut.com/starbase-tour-and-interview-with-elon-musk/)。顺序来自工程访谈；可逆试验、业务约束检查与输出格式为本项目商业场景改编。工程经验不是市场需求成立的证据。
